---

工作台和 CLI 提供 **默认模式（Standard）** 与 **Effect** 两种独立模式。它们的核心区别在于**代码模型的轻重**与**可选技术栈的范围**。

## 怎么选：默认模式 vs. Effect 模式 [#when]

|                  | **默认模式（Standard）**                                                                                    | **Effect 模式**                                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **适合什么项目** | 绝大多数常规项目                                                                                            | 服务链路较复杂、对错误处理和资源管理要求严格的项目                                                                             |
| **代码写法**     | 通用的 TypeScript 写法，上手即用                                                                            | 一套更重、约束更严的编程模型，把错误、依赖和资源回收纳入类型检查                                                               |
| **技术栈范围**   | 最广泛（支持 SPA、Next.js、TanStack Start、Hono、Expo 移动端、Electron 桌面端、四种数据库、Docker 与 Void） | 限制较严（目前支持 Node 上的 React 单页应用、PostgreSQL 或 SQLite 或无数据库、可选 Better Auth、可选 Electron 桌面端、Docker） |

- **选择默认模式**：如果你希望使用大家最熟悉的通用写法、零额外学习成本，或者需要服务端渲染（Next.js、TanStack Start）、移动端（Expo）、桌面端（Electron）、Cloudflare Workers（Void）等更广泛的技术选型。
- **选择 Effect 模式**：如果你的后端服务链路较复杂，希望通过一套更严谨的模型在编译期约束错误处理、服务依赖与资源释放，并且当前项目形态在 Effect 模式支持的技术栈范围内。

关于 Effect 本身的语法、概念与设计理念，请直接参阅 [Effect 官方文档](https://effect.website/docs/)。

## Effect 模式包含什么 [#stack]

切换到 Effect 模式后，生成的项目从前端到后端统一使用 Effect 生态（不再混用 Hono、oRPC、Zod 或 TanStack Query）：

- **前端、桌面端与接口**：React 单页应用（TanStack Router）配合 Effect 响应式状态与类型化 RPC/HTTP 接口，可选接入 Electron 桌面壳（`apps/desktop` 与 `packages/electron`，IPC 边界同样使用 Effect Schema 校验）。
- **数据与认证（可选）**：可选 PostgreSQL 或 SQLite（基于 Node 内置 SQLite，无需单独启动数据库服务），配合 Drizzle 管理数据表与迁移；启用数据库时可接入 Better Auth 登录认证。若选择无数据库，则仅生成精简的接口与健康检查骨架。
- **测试与开发体验**：包含服务端测试与浏览器端到端测试（默认 Playwright，可选 TesterArmy `e2e`），并在项目内附带了与当前版本一致的 Effect 本地文档供 AI 编程工具参考。

## 创建 Effect 项目 [#create]

在工作台中切换到 **Effect**，或在 CLI 中传入 `--mode effect`：

```sh
# 交互式创建 Effect 项目
pnpm dlx vibestart-cli my-app --mode effect

# 查看 Effect 模式支持的所有技术栈选项
pnpm dlx vibestart-cli --list --mode effect

# 无状态 Effect 服务（不含数据库与认证）
pnpm dlx vibestart-cli my-app --mode effect --database none --orm none --auth none
```

CLI 不会自动混搭两种模式的选项；包管理器（`pnpm` 或 `bun`）可自由选择。
