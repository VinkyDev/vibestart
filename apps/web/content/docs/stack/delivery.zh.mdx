交付决定应用如何到达用户：通过 Docker 部署到服务器、通过 Void 部署到 Cloudflare，或作为 Electron 桌面应用安装。各项均为可选项，Docker 和 Void 也可以添加到兼容的已有项目。

## Docker [#docker]

<Tech href="https://docs.docker.com" icon="docker" />

选择 Docker 后，项目包含生产 Dockerfile、Compose 配置和忽略文件。多阶段构建将依赖安装、应用构建和运行环境分开。构建阶段只安装和构建镜像要运行的应用及其依赖的包，同一仓库里的 Electron 应用不会进入构建。最终镜像包含应用运行所需的产物。

生成方式随技术栈调整：静态站点由 Web 服务器提供资源，SSR 应用运行服务端构建产物，Hono 使用所选的 Node.js 或 Bun 运行时。数据库文件和数据库服务的数据目录使用持久化存储。

在部署环境配置密钥与数据库地址后，使用项目生成的 Compose 配置启动服务。已有项目可通过 [`npx vibestart-cli add docker`](/docs/cli/add) 添加部署配置。

## Void（预览） [#void]

<Tech href="https://void.cloud" icon="void" />

Void 1.2.1 负责构建并部署到你自己的 Cloudflare Workers 账号。选择 `--deployment void --runtime workers` 可部署静态 SPA、由 Hono 托管的 SPA 或 TanStack Start。不支持 Next.js、独立 Hono 服务、TanStack Start + Hono 双服务组合。静态 SPA 只部署静态资源。使用 Hono 时，Cloudflare 直接提供 SPA 的静态资源，仅 `/api/*` 由 Worker 处理，因此 oRPC 位于 `/api/rpc`。

带数据库的服务端使用外部 PostgreSQL 或 MySQL + Drizzle，可选 Better Auth。SPA + Hono 技术栈可以不使用数据库。Hyperdrive 管理生产连接池；每个请求创建客户端，在响应流完成或失败后释放。不使用 Void 自带迁移和登录；不支持 SQLite、Prisma、MongoDB、D1 和 Void Platform。

首次部署带数据库的项目之前，先在 Cloudflare 控制台为生产数据库创建 Hyperdrive 配置，并**关闭查询缓存**。每次部署时在 shell 中设置其 ID 为 `HYPERDRIVE_ID`；`void.config.ts` 绑定这个已有资源。浏览器登录可以部署已有绑定，无需 Hyperdrive 编辑权限的 API token，但不能创建它。自动创建会启用查询缓存，写入不会使缓存失效，可能返回过期的待办列表或已撤销的会话。关闭缓存仍保留连接池；保持缓存关闭，并确保它与迁移地址指向同一数据库。

克隆后按生成的 README 重建本地 `.env`。带服务端的技术栈需在部署应用目录执行 `void prepare` 生成被忽略的 Worker 类型；安装依赖时也会通过 `prepare` 自动运行。Worker 与 Node 工具分别使用独立的 TypeScript 配置。

按 README 使用 `void connect --platform cloudflare` 登录，并用 `void secret put` 设置生产服务端变量。本地 `.env` 不会上传。带数据库的技术栈使用 `HYPERDRIVE_ID='<已关闭缓存的配置ID>' DATABASE_URL='生产地址' vp run deploy`，在执行 Drizzle 迁移之前校验这两个 shell 值，必要时构建 SPA，再执行 `void deploy`。数据库地址必须显式存在于部署命令的 shell，避免本地 `.env` 静默选中了迁移目标。这两个部署值不要写入 Worker secrets。提交记录部署状态的 `void.lock.json`；vibestart 维护命令不会生成或合并它。生成项目不包含 GitHub Actions。

PowerShell 中先设置 `$env:HYPERDRIVE_ID = '<已关闭缓存的配置ID>'` 和 `$env:DATABASE_URL = '生产地址'`，再执行 `vp run deploy`。不带数据库的技术栈只需 `vp run deploy`，无需数据库地址或 Hyperdrive。

`vibestart add void --dry-run` 可预览给没有服务端的 SPA 添加该部署，项目随后运行在 Workers 上。已有服务端的项目保留 Node.js 或 Bun 运行时：`add` 不会替换它，因为把服务端代码迁到 Workers 属于迁移。已有 Docker 同样不会被静默替换。

## Electron [#electron]

<Tech href="https://www.electronjs.org" icon="electron" />

Electron 将单页应用放入桌面窗口，页面代码与 Web 应用共享。`apps/desktop` 包含主进程、preload 和打包配置；`packages/electron` 定义进程间通信的通道、载荷 schema 与类型。

生成配置启用 `contextIsolation` 和 `sandbox`，关闭页面的 `nodeIntegration`。IPC 校验消息来源，外部链接交由系统浏览器打开。打包后的应用通过 `https://app.localhost` 加载页面，并在需要时代理 API 请求。

Electron 使用单页应用前端，通过 electron-builder 生成分发包。
