交付决定应用如何到达用户：通过 Docker 部署到服务器、通过 Alchemy 部署到云平台，或作为 Electron 桌面应用安装。各项均为可选项，Docker 和 Alchemy 也可以添加到兼容的已有项目。

## Docker [#docker]

<Tech href="https://docs.docker.com" icon="docker" />

选择 Docker 后，项目包含生产 Dockerfile、Compose 配置和忽略文件。多阶段构建将依赖安装、应用构建和运行环境分开。构建阶段只安装和构建镜像要运行的应用及其依赖的包，同一仓库里的 Electron 应用不会进入构建。最终镜像包含应用运行所需的产物。

生成方式随技术栈调整：静态站点由 Web 服务器提供资源，SSR 应用运行服务端构建产物，Hono 使用所选的 Node.js 或 Bun 运行时。数据库文件和数据库服务的数据目录使用持久化存储。

在部署环境配置密钥与数据库地址后，使用项目生成的 Compose 配置启动服务。已有项目可通过 [`npx vibestart-cli add docker`](/docs/cli/add) 添加部署配置。

## Alchemy（预览） [#alchemy]

<Tech href="https://alchemy.run" icon="alchemy" />

选择 `--deployment cloudflare-workers --runtime workers` 可将 React 或 Solid SPA、搭配 Hono 的 SPA 或 TanStack Start SSR 部署到自己的 Cloudflare 账号。静态 SPA 支持直接打开前端路由。搭配 Hono 时，Worker 处理 `/api` 和 `/api/*`（含 `/api/rpc`），Cloudflare 提供前端资源。Start 通过 Cloudflare Vite 插件同时构建 SSR Worker 和浏览器资源。

在生成的项目根目录执行 `vp exec alchemy profile edit --add Cloudflare` 连接账号。CI 中设置 `CLOUDFLARE_ACCOUNT_ID` 和 `CLOUDFLARE_API_TOKEN`。首次部署会在账号下创建保存状态的 Worker、Durable Object 和 Secrets Store 凭据。权限要求见 [Alchemy 状态存储说明](https://alchemy.run/state-store/)。

使用 PostgreSQL 或 MySQL 时，为生产数据库创建 Hyperdrive 并**关闭查询缓存**，然后在部署终端设置指向同一个数据库的 `HYPERDRIVE_ID` 和 `DATABASE_URL`。使用 Better Auth 时还需设置 `BETTER_AUTH_SECRET`。首次部署使用 Alchemy 提供的 Worker URL，自定义 HTTPS 域名可通过 `BETTER_AUTH_URL` 设置。部署脚本检查配置并执行 Drizzle 迁移。Worker 通过 Hyperdrive 为每个请求创建客户端，在响应流结束时释放连接。

执行 `vp run deploy` 发布到 `prod` 环境，再次执行会更新同一个部署。本地开发和检查使用 `vp run dev` 和 `vp run ready`。对没有服务端的已有 SPA，可运行 `vibestart add cloudflare-workers --dry-run` 预览配置变更。

## Cloud Run 和 Fly Machines [#cloud-containers]

独立的 Hono/Node.js API 可以选择 `gcp-cloud-run` 或 `fly-machines`。两个目标都生成 Alchemy stack，并复用同一应用选择在 Docker 部署下的 Dockerfile。发布 Linux AMD64 镜像后，将仓库路径和 SHA-256 摘要赋给 `DEPLOY_IMAGE`。部署平台需要有拉取镜像的权限。

Cloud Run 提供公开 HTTPS 服务。选择外部 PostgreSQL 和 Drizzle 时，Cloud Run Job 使用与服务相同的镜像执行迁移，成功后才更新服务版本。数据库连接地址通过 Secret Manager 的指定版本注入。Fly Machines 创建一台无状态 Machine，分配共享公网 IPv4，并配置 HTTPS 入口和健康检查。

两个目标使用 GCS 保存团队共享的部署状态，各自使用独立的前缀。选择 Fly 也需要能访问 GCP 状态项目。生成的 `DEPLOYMENT.md` 列出了账号、凭据和区域配置。在同一环境中运行 `vp run plan` 和 `vp run deploy`。可用 `ALCHEMY_STAGE=pr-42` 隔离预览，确认 stage 后用 `vp run destroy` 回收。自托管项目仍可选 `--deployment docker` 使用 Docker Compose。

## Electron [#electron]

<Tech href="https://www.electronjs.org" icon="electron" />

Electron 将单页应用放入桌面窗口，页面代码与 Web 应用共享。`apps/desktop` 包含主进程、preload 和打包配置；`packages/electron` 定义进程间通信的通道、载荷 schema 与类型。

生成配置启用 `contextIsolation` 和 `sandbox`，关闭页面的 `nodeIntegration`。IPC 校验消息来源，外部链接交由系统浏览器打开。打包后的应用通过 `https://app.localhost` 加载页面，并在需要时代理 API 请求。

Electron 使用单页应用前端，通过 electron-builder 生成分发包。
