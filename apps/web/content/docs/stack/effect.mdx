---
title: Effect mode
description: How Effect mode differs from the Standard stack, what it supports, and when to choose it.
---

Studio and the CLI offer **Standard** (the default) and **Effect** as two independent modes. They differ in **how heavy the programming model is** and **how wide a range of stacks they support**.

## How to choose: Standard vs. Effect [#when]

|                  | **Standard mode**                                                                                           | **Effect mode**                                                                                                                           |
| ---------------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Best for**     | Most projects                                                                                               | Projects with complex service flows and strict reliability requirements                                                                   |
| **Coding model** | Familiar TypeScript with no extra learning curve                                                            | A heavier, stricter model that checks errors, dependencies, and resource cleanup in types                                                 |
| **Stack range**  | Widest (SPA, Next.js, TanStack Start, Hono, Expo mobile, Electron desktop, four databases, Docker and Void) | Focused (React SPA on Node, PostgreSQL or SQLite or no database, optional Better Auth, optional Electron desktop and Expo mobile, Docker) |

- **Choose Standard** for general projects when you want familiar, everyday TypeScript and the full range of frameworks (SSR, SPA, standalone APIs), databases, runtimes, and deployment targets.
- **Choose Effect** when you have complex backend service flows, want a stricter model that enforces error handling and resource management at compile time, and fit within its supported stack choices.

To learn Effect's concepts and syntax in detail, see the [official Effect documentation](https://effect.website/docs/).

## What Effect mode includes [#stack]

When you select Effect mode, the generated project uses the Effect ecosystem end to end rather than mixing in Hono, oRPC, Zod, or TanStack Query:

- **Web, desktop, mobile, and API**: A React single-page app (TanStack Router) paired with Effect's HTTP/RPC server and reactive client state, with an optional Electron desktop shell (`apps/desktop` and `packages/electron`) and an optional Expo mobile app (`apps/mobile`) sharing the same `packages/contracts` schemas and Effect Atom clients.
- **Database and auth (optional)**: Choose PostgreSQL, SQLite (using Node's built-in SQLite with no separate database server), or no database at all. With a database, you can include Better Auth for sign-in, or omit auth for public data.
- **Testing and AI context**: Includes service tests, browser end-to-end tests (Playwright by default, or TesterArmy `e2e`), and local Effect documentation wired for coding agents.

## Creating an Effect project [#create]

Switch to **Effect** in the Studio, or pass `--mode effect` to the CLI:

```sh
# Interactive creation in Effect mode
pnpm dlx vibestart-cli my-app --mode effect

# List all supported choices in Effect mode
pnpm dlx vibestart-cli --list --mode effect

# Stateless Effect app (no database or auth)
pnpm dlx vibestart-cli my-app --mode effect --database none --orm none --auth none
```

The CLI rejects mixed selections between Standard and Effect rather than switching modes automatically. Both `pnpm` and `bun` are supported as package managers.
