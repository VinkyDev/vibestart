---
title: Effect mode
description: An independent stack built around Effect services, schemas, RPC, and atoms.
---

Studio starts in **Standard** mode. Switch to **Effect** to work with the reviewed Effect stack; switching modes selects that mode's defaults. The URL records the mode, and browser Back restores the previous selection.

```sh
pnpm dlx vibestart-cli my-app --mode effect
pnpm dlx vibestart-cli --list --mode effect
```

Effect mode uses React and TanStack Router, Effect HTTP and RPC, `@effect/atom-react`, and optional persistence and authentication. Validation uses Effect Schema. Server dependencies are composed with Layers; typed service errors become sanitized transport errors. Browser state belongs to atoms, including session-scoped RPC state. There is no parallel Hono, oRPC, Zod, or TanStack Query stack.

`packages/contracts` owns shared schemas and protocols. `packages/api` owns handlers and services, `packages/db` owns persistence when selected, and `packages/auth` adapts Better Auth when selected. `apps/server` composes and launches the application; `apps/web` owns routes and presentation. Third-party Promise APIs are adapted at their service boundary.

Choose PostgreSQL (`@effect/sql-pg`) or SQLite (`@effect/sql-sqlite-node` on Node's built-in SQLite). Both use Drizzle's native Effect queries and migrations, on the same Effect version as the application. SQLite needs no database server. Better Auth is optional but requires a database; its official Drizzle adapter is scoped at the service boundary.

With a database and no auth, todos are public and shared. With no database, the generator omits the ORM, auth, migrations, and todo example, and keeps typed HTTP/RPC health checks. The RPC boundary checks browser origins against `BETTER_AUTH_URL` when auth is enabled, or `APP_URL` otherwise.

```sh
pnpm dlx vibestart-cli my-app --mode effect --database sqlite --auth none --testing playwright
pnpm dlx vibestart-cli my-app --mode effect --database none --orm none --auth none
```

The supported runtime is Node. Choose Docker or no deployment; unadapted frameworks, databases, mobile apps, desktop shells, and runtimes are unavailable. The CLI rejects mixed selections rather than changing modes. The package manager remains independent: pnpm and Bun can install the same Node application.

Tests use `@effect/vitest` for services and Playwright (the default) or TesterArmy `e2e` for browser flows. Both run the real Effect server and use scoped test resources. The generated golden participates in the same verification matrix as Standard projects. Docker CI also exercises migrations, authentication, and authenticated RPC against the production image.

[Effect documentation](https://effect.website/docs/) explains the runtime and service model.
