## Rendering options [#choose]

Choose a browser-rendered React or Solid SPA, or a React framework with server rendering:

| Option         | Rendering and deployment                                | Use cases                              |
| -------------- | ------------------------------------------------------- | -------------------------------------- |
| Vite           | Browser rendering; static hosting or Hono               | Dashboards, tools, desktop apps        |
| TanStack Start | Server rendering; Node.js service                       | Full-stack apps using TanStack routing |
| Next.js        | App Router and React Server Components; Node.js service | Content sites and full-stack products  |

## Solid 2 [#solid]

Choose **Solid 2** in the Studio or pass `--frontend solid` to the CLI. The generated Vite SPA uses Solid Router and the Solid UI SDK adapter. It can run as a static site or use Hono with the same database and ORM choices as the standard React SPA.

Choose OpenAPI or oRPC with a database to generate a typed todo list at `/todos`. Better Auth adds email sign-in and keeps each user's todos private. Electron can wrap the Solid web app, and an optional Expo mobile app can share its API.

This command adds PostgreSQL and an editable Alchemy stack.

```bash
npx vibestart-cli my-app --frontend solid --backend hono --api orpc --database postgres --orm drizzle --auth better-auth --addons alchemy,knip,ultracite
```

## React [#react]

<Tech href="https://react.dev" icon="react" />

React organizes the interface into components. Generated projects include pages, forms, shared components, and React Compiler configuration. State and events use standard React APIs.

## Vite [#spa]

<Tech href="https://tanstack.com/router" icon="tanstack" paired="vite" />

Vite builds the SPA. React uses TanStack Router file routes, and Solid registers routes in `apps/web/src/router.tsx`. Paths, parameters, and navigation are type checked. Without a backend, deploy static assets. With Hono, the production service can serve both pages and APIs.

## TanStack Start [#tanstack-start]

<Tech href="https://tanstack.com/start" icon="tanstack" />

TanStack Start adds server rendering, server routes, and server functions to TanStack Router. The project builds with Vite and produces server output through Nitro. Use framework routes or a separate Hono service for the backend.

## Next.js [#next]

<Tech href="https://nextjs.org" icon="next" />

Next.js projects use App Router and React Server Components. Server components access server data; interactive components use a client boundary. Generated configuration includes React Compiler. Project tasks call Next.js development and build commands.

## Routing [#tanstack-router]

The React SPA and TanStack Start use TanStack Router. The Solid SPA registers routes in `apps/web/src/router.tsx`. Next.js uses App Router. Add React pages in the route directory for the selected framework.

## TanStack Query [#tanstack-query]

<Tech href="https://tanstack.com/query" icon="tanstack" />

TanStack Query manages server-data caching, loading state, and refreshes. oRPC supplies typed query options such as `api.todos.list.queryOptions()`. Refresh related queries after a write to keep the UI consistent with server state.

## shadcn/ui and Tailwind CSS [#shadcn]

<Tech href="https://ui.shadcn.com" icon="shadcn" paired="tailwind" />

Shared component source lives in `packages/ui` and can be edited directly. Base UI handles keyboard interaction and focus management; Tailwind CSS provides styling and themes. Selecting Ultracite also enables the corresponding shadcn lint rules.

## UI SDK [#ui-sdk]

Every React stack can switch between shadcn/ui and UI SDK while keeping its other choices. Solid 2 uses UI SDK.
