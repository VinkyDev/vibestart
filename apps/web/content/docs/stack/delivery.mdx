Delivery is how the finished application reaches its users: through Docker on a server, Alchemy on Cloudflare, or an Electron desktop app. Each is optional; Docker and Alchemy can also be added to compatible existing projects.

## Docker [#docker]

<Tech href="https://docs.docker.com" icon="docker" />

Selecting Docker adds a production Dockerfile, Compose configuration, and ignore file. Multi-stage builds separate dependency installation, application builds, and the runtime. The build stage installs and builds only the apps the image runs and the packages they use, so an Electron app in the same repository stays out. The final image contains the output needed to run the application.

Output follows the selected stack: static sites use a web server, SSR applications run their server build, and Hono uses the selected Node.js or Bun runtime. Database files and service data directories use persistent storage.

Configure secrets and database addresses in the deployment environment, then start services with the generated Compose configuration. Add deployment files to an existing project with [`npx vibestart-cli add docker`](/docs/cli/add).

## Alchemy (preview) [#alchemy]

<Tech href="https://alchemy.run" icon="alchemy" />

Select `--deployment alchemy --runtime workers` to deploy a React or Solid SPA, a SPA with Hono, or TanStack Start SSR to your Cloudflare account. A static SPA uses Cloudflare assets with history fallback. With Hono, the Worker handles `/api` and `/api/*`, including `/api/rpc`, while Cloudflare serves the frontend. Start builds both the SSR Worker and browser assets with the Cloudflare Vite plugin.

From the generated workspace, run `vp exec alchemy profile edit --add Cloudflare`. In CI, set `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN`. The first deployment bootstraps an account-level state Worker, Durable Object and Secrets Store credentials. Follow the [state store setup](https://alchemy.run/state-store/) for the permissions these resources need.

For PostgreSQL or MySQL, provision Hyperdrive with **query caching disabled**. Export `HYPERDRIVE_ID` and `DATABASE_URL` for the same production database. If Better Auth is selected, export `BETTER_AUTH_SECRET`. Alchemy supplies the Worker URL on first deploy. Set `BETTER_AUTH_URL` for a custom HTTPS origin. The deployment script checks the prerequisites and runs Drizzle migrations. The Worker uses the Hyperdrive binding and obtains a client per request. It releases that client after the response stream ends.

Run `vp run deploy` to publish the `prod` stage. Repeat the command to update the same stack. Use `vp run dev` and `vp run ready` for local work. `vibestart add alchemy --dry-run` previews adding Alchemy to a SPA without a server.

## Electron [#electron]

<Tech href="https://www.electronjs.org" icon="electron" />

Electron wraps the SPA in a desktop window while sharing page code with the web app. `apps/desktop` contains the main process, preload, and packaging configuration. `packages/electron` defines IPC channels, payload schemas, and types.

Generated settings enable `contextIsolation` and `sandbox` and disable page-level `nodeIntegration`. IPC checks message sources; external links open in the system browser. Packaged apps load pages through `https://app.localhost` and proxy API requests when needed.

Electron uses the SPA frontend and electron-builder to produce distribution packages.
