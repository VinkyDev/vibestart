## 三个组成部分 [#parts]

大多数 Web 应用由三部分组成：

- **前端**：用户看到并与之交互的页面，运行在用户设备的浏览器中。
- **后端**：接收请求、执行业务规则、读写数据的服务器，运行在由你掌控的机器上。
- **数据库**：在请求之间、重启之后持久保存数据的地方。

前端与后端通过 **API** 通信。API 定义了一组操作，以及每个操作的输入、输出和可能返回的错误。浏览器中的一切都可能被用户查看或修改，因此业务规则必须在后端执行。

## 跟随一次请求 [#request-flow]

以已登录用户创建一条待办为例，请求会依次经过各个部分：

<Journey
  steps={[
    {
      from: "browser",
      to: "server",
      text: "页面通过 API 客户端发送创建请求，并附带用户的登录会话。",
      code: "POST /rpc/todos/create",
    },
    {
      at: "server",
      text: "服务端读取会话以确认用户身份，然后校验输入。",
      code: "z.object({ title: z.string().trim().min(1).max(200) })",
    },
    {
      from: "server",
      to: "database",
      text: "查询将待办内容与当前用户的 ID 一起写入数据库。",
      code: "INSERT INTO todos (title, user_id) VALUES (…) ",
    },
    {
      from: "server",
      to: "browser",
      text: "API 返回新建的待办，页面刷新依赖它的查询。",
      code: "200 OK",
    },
  ]}
/>

<Callout type="warn" title="在服务端校验">
  浏览器中的校验能让用户更快得到反馈，但可以被绕过。服务端会独立校验每一个请求，密钥和数据库连接也只存在于服务端。
</Callout>

## 渲染与路由 [#rendering]

渲染是把数据转换成浏览器可以显示的 HTML。单页应用（SPA）在浏览器中渲染：服务器发送 JavaScript，再由它构建页面。服务端渲染（SSR）在服务器上生成 HTML，内容随首次响应一同到达，之后再由浏览器接管交互。

路由负责把 URL 映射到页面，并处理 `/todos/42` 这样的路径参数。vibestart 提供 TanStack Router 单页应用、TanStack Start 和 Next.js 三种选择，对比见[前端](/docs/stack/frontend)。

## API 与数据 [#data]

API 描述客户端可以请求服务器做什么。vibestart 提供两种形式：oRPC 在服务端与客户端之间共享 TypeScript 类型；OpenAPI 描述标准的 REST 接口，任何语言的客户端都可以调用。

数据库以表的形式保存数据。Drizzle 用 TypeScript 定义这些表，并构建带类型的查询。表结构变化时，**迁移**会将变化记录为 SQL，让从本机到生产环境的每个数据库都能按相同顺序应用。详见[后端与 API](/docs/stack/backend)和[数据与认证](/docs/stack/data)。

## 身份与权限 [#auth]

认证确认请求来自谁，授权决定此人可以访问什么。Better Auth 负责注册、登录和会话管理；授权仍属于应用自身的职责：每一个读写用户数据的查询，都要限定在当前用户的范围内。

例如，列出待办时会按会话中的用户 ID 过滤。前端的路由保护只负责把未登录的访客引导到登录页，真正保护数据的是 API 中的权限检查。

## 开发与生产 [#deployment]

开发时，`vp run dev` 同时启动前端和后端，在你编辑代码时自动重新加载，并把页面发出的 API 请求转发给服务器。生产构建会将应用编译为无需开发工具即可运行的文件。

Docker 将构建好的应用及其运行环境打包成镜像，在任何机器上都以相同方式运行。Compose 描述应用、数据库等多个服务如何一起启动。详见[交付](/docs/stack/delivery)。
