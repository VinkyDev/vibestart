---
title: 添加能力
description: 为已有项目添加代码检查工具或部署目标。
---

```sh
npx vibestart-cli add --list
npx vibestart-cli add knip ultracite docker --dry-run
npx vibestart-cli add knip ultracite docker --yes
```

未指定能力时，终端中会显示多选列表。代码检查工具包括 Knip 和 Ultracite。Docker 和 Alchemy 可独立添加。添加能力不会改变项目的包管理器和应用运行时。

## 预览与应用 [#apply]

`--dry-run` 展示文件与配置变更，不写入项目。确认后运行带 `--yes` 的命令，或在终端中确认计划。写入要求项目位于 Git 仓库中。请先提交或储藏项目目录内的所有改动，包括未跟踪的文件。冲突会直接写进相应文件，详见[用 Git 审查与撤销](/docs/cli/upgrade#git)。

`vibestart.jsonc` 记录的版本与运行中的 CLI 不同时，先执行 [`upgrade`](/docs/cli/upgrade)。已有能力不会重复添加。

## 安装与检查 [#checks]

默认安装依赖一次，然后执行 `vp check`、已选择的 Knip，以及存在的 `unit` 测试项目。对于 pnpm 项目，如果 PATH 中没有 pnpm，CLI 会通过 `npx` 提供 pnpm。`--full-check` 改为执行完整的 `vp run ready`。

`--no-install` 只写文件，返回 `needs-install`，并给出需要执行的安装与检查命令。这两个参数不能同时使用。

接入 Ultracite 后，已有业务代码可能需要按新增规则调整。检查失败时，文件保持已写入的状态：修改代码后重新执行检查，或用 Git 撤销。添加能力不会自动迁移数据库。

勾选 **Alchemy** 会生成可编辑的 `alchemy.run.ts`。初始栈使用本地状态，不创建云资源。在项目中安装需要的 provider 包，注册 provider 并声明资源；同一个栈可以组合多个厂商。需要生产镜像时可同时勾选 **Docker**。配置共享状态后再从 CI 部署。使用 `vp run plan --stage dev` 查看变更，使用 `vp run deploy --stage dev` 部署。已有项目可运行 `vibestart add alchemy`。
