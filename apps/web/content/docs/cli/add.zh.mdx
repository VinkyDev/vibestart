---
title: 添加能力
description: 为已有项目添加代码检查工具或部署目标。
---

```sh
npx vibestart-cli add --list
npx vibestart-cli add knip ultracite docker --dry-run
npx vibestart-cli add knip ultracite docker --yes
```

未指定能力时，终端中会显示多选列表。代码检查工具包括 Knip 和 Ultracite。部署目标包括 Docker Compose、Cloudflare Workers、Google Cloud Run 和 Fly Machines。添加能力不会改变项目的包管理器和应用运行时。

## 预览与应用 [#apply]

`--dry-run` 展示文件与配置变更，不写入项目。确认后运行带 `--yes` 的命令，或在终端中确认计划。与升级相同，写入要求 Git 工作区干净，冲突会直接写进文件，详见[用 Git 审查与撤销](/docs/cli/upgrade#git)。

`vibestart.jsonc` 记录的版本与运行中的 CLI 不同时，先执行 [`upgrade`](/docs/cli/upgrade)。已有能力不会重复添加。

## 安装与检查 [#checks]

默认安装依赖一次，然后执行 `vp check`、已选择的 Knip，以及存在的 `unit` 测试项目。对于 pnpm 项目，如果 PATH 中没有 pnpm，CLI 会通过 `npx` 提供 pnpm。`--full-check` 改为执行完整的 `vp run ready`。

`--no-install` 只写文件，返回 `needs-install`，并给出需要执行的安装与检查命令。这两个参数不能同时使用。

接入 Ultracite 后，已有业务代码可能需要按新增规则调整。检查失败时，文件保持已写入的状态：修改代码后重新执行检查，或用 Git 撤销。添加能力不会自动迁移数据库。

`add cloudflare-workers` 可将没有服务端的 SPA 部署到 Cloudflare：这类项目尚无运行时，Alchemy 将其作为静态资源部署到 Workers。已有服务端的项目运行在 Node.js 或 Bun 上，`add` 不会替换其运行时，因为把服务端代码迁到 Workers 属于迁移；请改用 `--deployment cloudflare-workers --runtime workers` 创建新项目。已有部署不会被隐式替换。详见 [Alchemy 部署](/docs/stack/delivery#alchemy)。

独立的 Node/Hono API 可以用 `add gcp-cloud-run` 或 `add fly-machines` 添加兼容的部署目标。用 `--dry-run` 查看改动，再按生成的 `DEPLOYMENT.md` 配置部署。
