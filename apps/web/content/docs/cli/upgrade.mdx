---
title: Upgrade a project
description: Preview template updates while preserving application changes.
---

```sh
npx vibestart-cli upgrade --check
npx vibestart-cli upgrade --dry-run
npx vibestart-cli upgrade --yes
```

`--check` reports available updates and exits with `1` when an update is found. `--dry-run` shows the merge plan without writing. The default target is the template release bundled with the running CLI.

## Target release [#target]

Run the desired CLI version or use `--to <exact-published-version>`. The target CLI generates its own output, keeping templates and catalog on the same release. Use the same exact CLI version for preview and application; `--to` accepts a published version number, not the `beta` or `latest` tag.

## Merge scope [#merge]

Upgrades perform a three-way merge of the original template, current project, and target template, preserving mergeable JSONC comments, custom scripts, and configuration fields. Application pages and API implementations remain project-owned. Target changes to existing application source require a reviewed migration before the baseline can advance.

The default installs dependencies and runs static checks, selected Knip checks, and existing unit tests. Use `--full-check` for the complete `vp run ready`. With `--no-install`, finish the retained operation through `recover` before making another maintenance change.

Maintenance does not initialize, migrate, or reset databases. Review and execute production data migrations separately.

## Conflicts [#conflicts]

If application encounters conflicts, project files are not written. Candidates are saved in `.vibestart/pending/candidates/`. Review them, resolve conflict markers, and run `npx vibestart-cli recover --yes`. Previews do not create candidates.

See [recovery](/docs/cli/recover) for resume and rollback behavior.

## Adopt an older project [#adopt]

```sh
npx vibestart-cli adopt --from original-snapshot.json --dry-run
npx vibestart-cli adopt --from original-snapshot.json --yes
```

`adopt` requires a separately retained original generation snapshot and confirmed project name and technology choices. The snapshot must use the CLI baseline format. A recipe or current application files cannot replace it.

This records provenance without installing or running checks. Unknown origins are not inferred automatically.
