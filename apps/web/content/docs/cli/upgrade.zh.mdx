---
title: 升级项目
description: 基于模板版本预览更新，保留项目中的业务修改。
---

```sh
npx vibestart-cli upgrade --check
npx vibestart-cli upgrade --dry-run
npx vibestart-cli upgrade --yes
```

`--check` 检查是否存在更新，发现更新时退出码为 `1`。`--dry-run` 展示合并计划，不写文件。默认目标是运行中的 CLI 所携带的模板版本。

## 原始模板从哪里来 [#base]

`vibestart.jsonc` 记录项目名 `name`，以及生成项目的版本 `version`。升级时，CLI 按项目的技术选择重新生成该版本的模板，作为三方合并的基准。生成过程是确定的，已发布的版本也不会改变，因此重新生成的结果与项目最初的模板一致。项目中不需要另存其他文件。

记录的版本与运行中的 CLI 不同时，CLI 会从 npm 运行该版本来重新生成模板，需要能访问 npm。

## 目标版本 [#target]

运行目标版本的 CLI，或使用 `--to <精确版本号>` 指定目标。目标版本由对应的 CLI 生成，确保模板与 catalog 来自同一版本。预览与应用应使用同一个精确 CLI 版本；`--to` 接受已发布的版本号，不接受 `beta` 或 `latest` 标签。

## 合并范围 [#merge]

模板持续维护的文件会进行三方合并：原始模板、当前项目文件和目标模板。这些文件包括各个 `package.json`、catalog、TypeScript 与 Vite+ 配置、Knip、Git 忽略规则、`AGENTS.md` 和 Docker 文件。合并会保留可合并的 JSONC 注释、自定义脚本及配置字段。最后，CLI 将目标版本写入 `vibestart.jsonc`。

业务页面、API 实现等初始业务源码归项目所有。目标模板修改了这类文件时，计划会把它列在 `manual` 下，并附上模板自身的差异，升级不会写入这些文件。请把这些变化移植到你的代码中，也可以交给编码 Agent 完成。项目中已经做过的修改不会再列出。

默认安装依赖并执行静态检查、已选 Knip 与存在的单元测试。使用 `--full-check` 执行完整 `vp run ready`。`--no-install` 只写入文件，并给出需要执行的安装与检查命令。

维护命令不初始化、迁移或重置数据库。生产数据迁移应单独审查和执行。

## 用 Git 审查与撤销 [#git]

写入要求项目位于 Git 仓库中，且没有未提交的修改，这样 `git diff` 显示的正好是本次升级的全部改动。提交前请先审查。如需全部撤销，执行 `git restore . && git clean -fd`。预览没有这项要求。

## 冲突 [#conflicts]

同一处既有你的修改、也有模板的变化时，CLI 会把两边的内容都写进文件，用 Git 的冲突标记（`<<<<<<< project`、`=======`、`>>>>>>> target template`）分隔，并在安装前停止。解决冲突标记后，执行结果中给出的安装与检查命令。被删除的维护文件会被恢复，同样报告为冲突。预览只报告冲突，不写入文件。
